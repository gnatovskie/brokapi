# Допущения по документации брокеров

Для ИИ-агентов, которые пишут код для боевого счета. Все брокеры запускались на настоящих счетах (что именно проверено - раздел «Что проверено вживую» на странице брокера). Ниже то, что взято из документации
брокера и вживую не проверялось, поэтому может оказаться иначе. Сначала [before-live.md](../before-live.md). Допущение, на которое опирается ваш код, проверьте
на минимальной заявке и не выдавайте за подтвержденное.

## Все брокеры

| Допущение | Что делать |
|---|---|
| Что брокер сделает с повтором того же `cid`, неизвестно (`PlaceIdempotency::LabelOnly`) | `place` не повторять. `Unknown` выясняйте через `order_state`, новая попытка идет с новым `cid` |
| Области и значения лимитов взяты из документации | Один `BrokerLimiter` на область. Если `RateLimited` приходит раньше времени, уменьшите значения в `limits.toml` |
| Срок жизни токенов и потоков не назван | Обрыв виден событием `Reconnected` и закрытым шлюзом: после него `reconcile` |
| Чистка кадров и тел на `trace` (с версии 0.1.0-alpha.11) находит поля с номером счета и токенами по их именам, известным из документации и записанных ответов брокеров | Лог на `trace` с боевого счета не пересылайте и не выкладывайте, не просмотрев. На `info` и `debug` тел и кадров нет |

## БКС

| Допущение | Что делать |
|---|---|
| `GET /orders` по неизвестному `cid` отвечает `NOT_FOUND` | Иначе сверка отнесет заявку к неопределенным: первую сверку сделайте на минимальной заявке |
| Количество в заявке в штуках, в уровнях стакана и ленты единица не названа | Не умножайте на лот, объем сверяйте с количеством своей заявки |
| Синхронные методы: сколько ждут, как выглядит отказ, повтор `clientOrderId` | `Unknown` не повторять |
| Какой из `clientOrderId` и `originalClientOrderId` несет `cid` в `orders/events/ws` | `cid` из событий сверяйте с журналом |
| Условные заявки: срок жизни, смысл `price`, потока статусов нет | Только срок «до отмены», стопы читайте через `active_stop_orders()` |
| Сработавший стоп: под каким `cid` приходят его сообщения в `orders/events/ws` (сделано по тому же `cid`, вживую срабатывание не видели). Стоп из приложения в сообщении не отличить от заявки | Первый настоящий стоп проверьте на минимальной позиции. Стопы, поставленные не через `place_stop`, в потоке заявок приходят как заявки |
| Подписка на котировки: подтверждения в документации нет, коннектор считает ее открытой, если за 3 с не пришло ни подтверждения, ни котировки, ни ошибки (допущение) | Первую котировку ждите по событию, а не по возврату `subscribe_quotes` |
| Позиция и остаток после сделки: БКС дает строку на каждый срок расчетов (`T0`, `T1`, `T2`, `T365`), библиотека сводит их в одну по самому длинному сроку. Проверено на имитации и по записи ответа 09.11, живой повтор на исправленной версии не делался | После сделки сверяйте позицию с исполнениями, первую сделку делайте на минимальном объеме |
| История сделок (`executions`): номер сделки (`tradeNum`) и номер заявки (`orderNum`, без даты и площадки) того же вида, что и в потоке, не проверены (допущение: нумерации разные, вживую история с настоящей сделкой не читалась) | После обрыва потока сверяйте историю с потоком по заявке, цене и количеству, не по `trade_id` |
| Количество при `replace` частично исполненной заявки (весь объем или остаток) | Указывайте количество явно |
| Что приходит в `orders/events/ws` после переподключения | После `Reconnected` делайте `reconcile` |
| Как БКС считает секунду и сутки. Суточный лимит считает только ваш процесс | Один процесс на счет |

## Т-Банк

| Допущение | Что делать |
|---|---|
| Повтор `order_id` на боевом счете (на песочнице отказ `30057`, первая заявка остается) | `PostOrder` не повторять, ждать `Unknown` и спрашивать `order_state` |
| Повтор `order_id` стоп-заявки: ключ идемпотентности или вторая заявка | `place_stop` не повторять |
| `create_date` стопа в `GetStopOrders` совпадает со временем отправки (допуск 10 секунд): по нему коннектор связывает стоп с потерянным ответом и `cid` | После `Unknown` стоп с `cid: None` на той же бумаге и в ту же сторону считайте возможно своим, второй не ставьте |
| Количество в потоке своих сделок в штуках (по `.proto`) | Объем сверяйте со своей заявкой |
| Цена в потоке чужих заявок: за бумагу или за лот | Не опирайтесь на цену чужих заявок |
| `ReplaceOrder`: цена при пустом поле, смена биржевого номера | Ориентируйтесь на `cid`, не на биржевой номер |
| Лимит песочницы 2 заявки в секунду (`ResourceExhausted` на вторую в ту же секунду, 14.11.2026), у боевого адреса другие значения | Не отправляйте на песочницу больше двух заявок в секунду |
| Действительные лимиты (15 в секунду на `PostOrder`, 100 в минуту на сервис заявок) | Реальные значения читайте через `raw()`: `GetUserTariff`, `x-ratelimit-*` |

## Финам

| Допущение | Что делать |
|---|---|
| Повтор `client_order_id` | Не повторять |
| Комиссия в истории сделок `Trades` (на живом счете не пришла) | Расход считайте по деньгам счета, `commission = 0` не значит бесплатно |
| Номер сделки `trade_id` у Финама: на живом счете он совпал с номером заявки, у частичных исполнений одной заявки он может повторяться (допущение, частичных исполнений вживую не было) | Не отсеивайте исполнения по одному `trade_id`: берите вместе с ним время, цену и количество |
| JWT в заголовке без `Bearer` | При отказе сервера включите `FinamApiConfig::bearer` |
| Стартовый срез в потоках, завершенные заявки в `GetOrders` | Состояние читайте запросом, срез не ждите |
| Область лимитов (секрет, пользователь или счет) | При раннем `RateLimited` уменьшите значения |

## АЛОР

| Допущение | Что делать |
|---|---|
| Единицы объема в стакане, ленте и свечах не названы (у котировок - лоты) | Берите количество как пришло |
| Повтор `X-REQID` возвращает копию ответа, срок памяти не назван | Коннектор команды не повторяет, и ваш код не должен |
| Регистр `condition`, `side`, `timeInForce`, срок стоп-заявки без времени окончания | Задавайте срок явно |
| Заявки в потоке после переподключения, заявки из приложения | После `Reconnected` делайте `reconcile` |
| История сделок свыше 1000 записей, реальные пределы (100 запросов в секунду, 5000 подписок) | Историю читайте окнами |

## Bybit

Bybit проверен вживую (подробности: [Bybit](../brokers/bybit.md#что-проверено-вживую)). Не проверено:

| Допущение | Что делать |
|---|---|
| Срабатывание стоп-заявки (стоп ставился и снимался, цена до него не доходила), поведение стопа на основном контуре | Первый настоящий стоп на минимальной позиции, дождитесь срабатывания |
| Переподключение приватного потока по истечении срока его жизни и потеря событий заявки за время обрыва | После `Reconnected` делайте `reconcile` |
| Лимиты: бан по адресу (HTTP 403), счет лимитов демо-счета и основного контура | Не превышайте 10 команд в секунду, при раннем `RateLimited` уменьшите значения в `limits.toml` |
| Режим позиции с хеджированием, смена плеча и режима маржи | Односторонний режим, плечо ставьте до первой заявки через `raw()` |
| Формулы `available` и `blocked` для нескольких монет в залоге и портфельной маржи | Для сумм, от которых зависит бот, читайте кошелек через `raw()` |
| Курсор страниц при более чем 50 заявках, история исполнений длиннее одного окна в 7 дней | Читайте историю короткими периодами |
| Сколько времени биржа помнит закрытый `orderLinkId` (`PlaceIdempotency::LabelOnly`) | Никогда не повторяйте `cid` |
| Минимальная стоимость заявки и предельное количество не проверяются локально | Считайте самую малую заявку сами, отказ придет `Rejected { code: "bybit_<код>" }` |
